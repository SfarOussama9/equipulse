# EquiPulse

An HR analytics platform that predicts employee burnout risk, explains each prediction, and helps
managers act on it. Built at the SMU Hackathon 2025.

All employee data is **synthetic**, generated by `data1.py`: real HR data is confidential.

## Features

- **Burnout prediction**: a scikit-learn Random Forest predicts a burnout score (1–10) from workload,
  meetings, remote days, vacation, peer support, growth, commute and salary satisfaction.
- **Explanations**: SHAP values give the main drivers behind each high-risk prediction
  (for example "weekly hours"), so a manager sees *why* someone is flagged.
- **Inequity radar**: clusters workload profiles and compares each employee's hours with their
  department (z-score) to flag "hidden heroes" (overloaded individual contributors at high burnout
  risk) and "coasters" (underutilised senior staff).
- **Manager co-pilot**: Google Gemini writes per-department action plans and recognition messages.
  Without an API key it falls back to templates.
- **Dashboard**: team mood grid, burnout analysis, inequity radar and a rewards leaderboard.

## Architecture

```
data1.py ──> burnout_data_clean_*.csv ──> train_model.py ──> burnout_predictor_model.pkl
                                                                    │
React UI (Vite) ──HTTP──> FastAPI (app/) ──> prediction · explanation (SHAP) · inequity · manager (Gemini)
```

| Path | Contents |
|---|---|
| `data1.py` | synthetic workforce data generator |
| `train_model.py` | trains and saves the model (prints MAE and R² on a 20% hold-out) |
| `predict_burnout.py`, `explain_predictions.py`, `inequity_radar.py`, `manager_copilot.py` | the pipeline as standalone scripts |
| `app/` | FastAPI backend: `/predict`, `/explain`, `/inequity`, `/manager`, `/employees` |
| `UI/` | React 19 + Vite + Tailwind frontend |

## Setup

Requires Python 3.11 and Node.js 20+.

```bash
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

Optional: to use Gemini instead of the fallback templates, set your key before starting the backend
(`$env:GEMINI_API_KEY = "..."` in PowerShell, `export GEMINI_API_KEY=...` on macOS/Linux). For the
frontend, copy `UI/.env.example` to `UI/.env` and put the key there.

The trained model is not in the repository (it is ~150 MB). Train it once:

```bash
python train_model.py
```

## Run

Backend (http://127.0.0.1:8000, API docs at `/docs`):

```bash
uvicorn app.main:app --reload
```

Frontend (in a second terminal):

```bash
cd UI
npm install
npm run dev
```

To regenerate the data: `python data1.py`, then `python train_model.py`, then `python predict_burnout.py`,
`python explain_predictions.py` and `python inequity_radar.py`.
